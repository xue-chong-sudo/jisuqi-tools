## 1. 一句话定位

一个 **Win32 纯 C++ 自绘 GUI** 的 Windows 桌面全盘文件搜索工具：**后台遍历全盘建立索引 → 索引持久化到 `.idx` → 输入关键词毫秒级出结果 → 自绘列表/预览/右键菜单**。

**不使用任何第三方 UI 库**（无 Qt / MFC / wxWidgets / Dear ImGui）。所有界面元素（标题栏、按钮、列表、弹窗、菜单、滚动条、复选框）都是 GDI 手绘。

## 3. 如何构建

**前置**：本机装有 Visual Studio 2022，路径写在 `src/build.ps1` 顶部：

```powershell
$VS    = "D:\Visual Studio 2022"
$SDK   = "D:\Windows Kits\10"
$MSVCVER = "14.51.36231"
$SDKVER  = "10.0.26100.0"
```

**步骤**（在 PowerShell 中）：

```powershell
& "D:\workbuddy文件\全盘搜索\src\build.ps1"
```

脚本内部依次执行：

1. `rc.exe /fo app.res app.rc` —— 编译资源（图标 + DPI 清单）
2. `cl.exe /std:c++20 /O2 /MT /EHsc /utf-8 /W2 /c search_app.cpp` —— 编译（静态链接运行库，exe 无外部依赖）
3. `link.exe /SUBSYSTEM:WINDOWS /OUT:newsearch.exe search_app.obj app.res user32.lib gdi32.lib shell32.lib ole32.lib comctl32.lib gdiplus.lib dwmapi.lib shlwapi.lib advapi32.lib`

**发布**：把 `src/newsearch.exe` 复制到项目根并改名为 `全盘搜索.exe`。

> ⚠️ `data/` 目录是**相对 exe 所在目录**解析的（`GetExeDir() + "\\data"`）。
> 换机器或换目录跑，索引会自动重建，但配置不通用。

## 5. 数据模型

```cpp
enum Cat { CAT_ALL, CAT_IMG, CAT_DOC, CAT_VIDEO, CAT_AUDIO,
           CAT_ARCH, CAT_APP, CAT_LNK, CAT_DIR, CAT_OTHER, CAT_COUNT };
```

| 结构 | 用途 | 关键点 |
|---|---|---|
| `CatDef` | 分类名 + 主题色 | 列表角标、图标配色都取这里 |
| `Rec` | 索引里的一条记录 | `parent` 是目录下标；`nameOff/lowerOff` 指向 blob |
| `Vol` | 一个盘符 | `dirs[]` 目录表 + `nameBlob/lowerBlob` 字符串池 |
| `Res` | UI 层一条结果 | `name/dir/size/mtime/cat` + 预格式化字符串 |
| `Snapshot` | 全盘快照 | `vector<shared_ptr<Vol>>` |

**并发核心**：`std::atomic<std::shared_ptr<Snapshot>> g_snap`
- 索引线程构建新卷 → `CommitVol()` 原子替换整份快照（RCU，读侧无锁）
- 搜索线程 `g_snap.load()` 拿到不可变快照，安全遍历
- `epoch` 代次号：每次搜索 `++g_epoch`，旧结果回来时 `m->epoch != g_curEpoch` 直接丢弃，避免乱序覆盖

## 6. 线程模型（`std::jthread` + `stop_token`）

| 线程 | 函数 | 职责 |
|---|---|---|
| indexer | `IndexerThread` (390) | 遍历 `A:..Z:` 有效固定盘，用 `FindFirstFileExW(FindExInfoBasic)` 增量扫描；>6h 的 `.idx` 重建 |
| searcher | `SearcherThread` (459) | 收到请求 → 遍历快照 → 分词 AND 匹配 → `PostMessage(WM_APP_SEARCHDONE)` |
| pump | `IndexStatusPump` (2351) | 每 200ms 让状态栏刷新索引进度 |

搜索请求通过 `mutex + condition_variable` 传递（结构体 `Req`），搜索结果通过窗口消息回传 UI 线程——**所有 UI 更新都在主线程**，无显式加锁。

**索引格式 `.idx`（`WBSVOL1`，ver=1）**：
```
IdxHead: magic[8] | ver:u32 | buildTime:u64 | letter:u32 | nRecs:u64 | nDirs:u64
dirs:    { len:u16, utf8 bytes } × nDirs
recs:    RecP{ nameOff,nameLen,lowerOff,lowerLen,parent(u32), size(u64), mtime(u64), attrs(u32), cat(u8) } × nRecs
blobs:   nameLen:u64, nameBlob | lowerLen:u64, lowerBlob
```

## 7. 布局系统

- **`struct Layout gL`**（530 行）：所有区域矩形集中计算，绘制/命中测试共用，避免两处坐标不一致。
- **`ComputeLayout()`**（1115 行）：按窗口客户区尺寸重算全部矩形 + 移动搜索框子窗口。
- **`S(v)`**：DPI 缩放函数 `S(v) = (v * dpi + 48) / 96`，**所有尺寸必须过一遍**，否则 120 DPI 下会错位。
- **`enum Zone` + `ZoneAt(x,y)`**（601/609）：把客户区切成标题栏/按钮/面包屑/复选框/分类/列表/列头/预览/状态栏/滚动条，`WM_NCHITTEST` 与鼠标交互共用同一套判定。

**纵向分区**：标题栏(38) → 搜索行(64) → 筛选行(46) → 主区 → 状态栏(30)
**横向分区**：分类面板 | 分隔条(8) | 结果列表 | 分隔条(8) | 预览面板

**列宽模型**（第二轮需求 6 重写）：`nameW / pathW / sizeW` 各自持久化，`timeW` 弹性吸收剩余宽度；拖动时按 `innerW` 限幅（`minTime=S(130)`），保证**拖哪条线动哪条线**。

## 8. 无边框窗口的关键消息

| 消息 | 作用 |
|---|---|
| `WM_NCCALCSIZE` | 返回 0，移除系统标准框架（去黑框） |
| `WM_NCHITTEST` | 自定义命中：标题栏区域返回 `HTCAPTION` 以支持拖动/双击最大化，右上三块返回按钮区 |
| `WM_DPICHANGED` | 重建字体 + 按系统给的矩形调整窗口 |
| `DwmExtendFrameIntoClientArea` | 去掉原生边框残留 |
| 创建后 `SetWindowPos(..., SWP_FRAMECHANGED)` | 强制立即重算非客户区，否则首帧仍是标准边框 |
| `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)` | 窗口圆角（失败回退 `SetWindowRgn`） |

### 弹出层关闭模型（第三轮统一）

三个弹出层（`WbScopePopup` / `WbCtxMenu` / `WbTypeMenu`）**必须**遵守：

1. 创建为 `WS_POPUP | WS_EX_TOPMOST | WS_EX_TOOLWINDOW`
2. 创建后 `SetForegroundWindow(popup)` —— **临时接管前台**，否则切到别的应用时收不到关闭通知
3. `WM_KILLFOCUS` / `WM_KEYDOWN` / 点击外部 → `DestroyWindow`
4. `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`
5. 执行完菜单动作后 `SetForegroundWindow(g_hwnd)` 把前台还给主窗口

改动其中任何一个弹出层，务必同步另外两个。

## 10. 结果流转（改搜索逻辑看这里）

```
DoSearch()                  // 读搜索框文本 → 生成 epoch → 填 Req → 通知 searcher 线程
  ↓
SearcherThread              // 按 scope / scopeDir / sub 过滤 → 分词 lowercase → 逐个 AND 匹配
  ↓
DoneMsg{epoch, items, total}
  ↓
WM_APP_SEARCHDONE           // epoch 校验：过期则丢弃
  ↓
g_results = items
g_catCount[] 从 g_results 重新统计   ← 计数与列表严格同源（第三轮 #12）
  ↓
ApplySortAndView()  = SortResults() + RebuildView() + UpdateStatusText()
  ↓
g_view[]  → DrawList 只画可见行
```

**分类计数**：`g_catCount[CAT_ALL] = g_results.size()`，其余按 `r.cat` 累加。
因此「全部 = 各分类之和」是**恒等式**，不可能再对不上。
超过 `MAX_STORED`（10 万）时，状态栏会显示"共 N 个结果，仅显示前 M 条"。

```cpp

static std::wstring ExtKeyOf(const Res& r);   // 文件夹→"文件夹"；无扩展名→"(无扩展名)"；否则大写扩展名
```

- 下拉内容 = **当前分类下实际存在的格式 + 数量**，按数量降序；没有的不显示

## 14. 已知问题 / 注意事项

1. **系统目录权限**：`C:\Windows\servicing\LCU\...` 下的文件副本受 TrustedInstaller 保护，
   `ShellExecute` 会返回 5（拒绝访问），属系统行为而非程序缺陷。
2. **结果上限**：单次最多保存 10 万条（`MAX_STORED`），超出部分只在状态栏给出总数说明。
3. **防闪烁约束**（第二轮 #11）：
   - `ComputeLayout()` 里只在矩形**真的变化**时才 `MoveWindow(..., FALSE)`
   - 主窗口带 `WS_CLIPCHILDREN`，搜索框带 `WS_EX_COMPOSITED`
   - `WM_ERASEBKGND` 直接返回 1
   改这几处会让搜索框重新出现闪烁。
4. **拖动锚点**：滚动条拖动用 `double g_vscrollAnchor`，
   不要用整型存 0~1 的比例（会被截断成 0，导致滑块跳顶）。
5. **索引自动刷新**：`.idx` 超过 6 小时会重建；首次启动扫描全盘期间结果不完整。

## 15. 代码风格约定

- 全部 `static` 文件内全局，集中在对应章节声明处，便于按章节定位
- 命名：`g_` 前缀全局、`r` 矩形、`dc` 设备上下文、`cat` 分类
- 所有像素尺寸经 `S()` 缩放
- 绘制统一走 `FillRC / FillRcRounded / DrawTextRC`，不在业务代码里直接 GDI
- 注释里保留**需求溯源**（如「需求6」「第四轮 #4/#5」），方便回溯为什么这样写
