## 1. 背景与目标

**现状**：全盘搜索是独立进程。启动时全量遍历固定盘、写 `vol_X.idx`、按代码内常量缓存（**以当前源码常量为准，改造前 `grep SIX_HOURS_TICKS` 及刷新相关常量确认，不写死数字**）。窗口关闭即进程退出，重开重新载入索引（约 130MB）。文件增减不能实时反映。

**目标**：
1. 关闭搜索窗口后进程内存回落到低位（验收标准见 A1，附录 C 修订为双指标）；
2. 窗口关闭期间的文件变化，下次打开时无需全盘重扫即可看到（由监听线程的重扫写盘保证）；
3. 窗口打开期间，外部文件变化在防抖 + 重扫完成后可见（A4 = 实时生效）；
4. **不改主程序进程模型**，不合并进程，不复制 `WalkVolume`。

### 5.2 窗口生命周期改造

**现状**：`WM_CLOSE` / `WM_DESTROY` 走 `PostQuitMessage`，进程退出。

**改为**：

1. **`WM_CLOSE` 永远只隐藏，不退出**：
   - 停止当前搜索线程（若有）并 join；
   - 清空搜索结果容器（`clear()` + `shrink_to_fit()`）；
   - 清空 `LoadVol` 载入的索引容器（`g_snap` 置空快照，见附录 C.1-1）；
   - **调 `SaveConfig()`**（附录 C.1-8，原 `WM_DESTROY` 独有的保存动作）；
   - 调 `EmptyWorkingSet(GetCurrentProcess())` 兜底；
   - `ShowWindow(hwnd, SW_HIDE)`；
   - `return 0`。
2. **显式退出走独立入口**（D4，附录 C.4）：标题栏关闭按钮(`idx 3`)右键 → 弹出"退出"菜单。该入口：
   - 停所有监听线程 → join；
   - 停调度线程 → join；
   - `PostQuitMessage(0)`。
3. **退出信号 `WM_APP+101`**（C9）：主程序 `App::Quit` 向搜索窗口 `PostMessage(WM_APP+101)`；搜索窗口收到后执行与"退出菜单"相同的收尾流程。
4. **单实例唤醒**（现有 `g_wmActivate`）：找到已有窗口 → 若隐藏则 `ShowWindow(SW_SHOW)` + `SetForegroundWindow` → **重新 `LoadVol` 载入索引**（隐藏时已释放）。

**关键点**：索引只在"窗口可见"期间驻留；监听线程不持有全量索引，只在重扫瞬间临时构建、写盘、释放（可见时额外做一次快照切换，见 5.4）。

### 5.3 监听线程

每个固定盘（`DRIVE_FIXED`）一个监听线程，**同步** `ReadDirectoryChangesW`：

```
线程入口（每盘一个）：
  保存真实线程句柄（附录 C.1-2：禁止 GetCurrentThread() 伪句柄）
    → 线程内 DuplicateHandle(GetCurrentProcess(), GetCurrentThread(), ...) 存 g_listenThreadHandle[vol]
      或由主线程 OpenThread(THREAD_TERMINATE, FALSE, tid)
  hDir = CreateFileW(L"X:\\", FILE_LIST_DIRECTORY,
                     FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE,
                     NULL, OPEN_EXISTING, FILE_FLAG_BACKUP_SEMANTICS, NULL)
  循环 {
    ok = ReadDirectoryChangesW(hDir, buf[64KB], TRUE,
             FILE_NOTIFY_CHANGE_FILE_NAME | FILE_NOTIFY_CHANGE_DIR_NAME |
             FILE_NOTIFY_CHANGE_SIZE | FILE_NOTIFY_CHANGE_LAST_WRITE,
             &bytes, NULL, NULL, NULL);   // 同步
    if (!ok) {
      if (GetLastError() == ERROR_OPERATION_ABORTED) break;   // CancelSynchronousIo 打断
      else { 标脏该卷; break; }                               // 其他错误：标脏后退出，由调度兜底
    }
    if (bytes == 0) { 标脏该卷; continue; }                    // 附录 C.1-3：溢出必须标脏，禁止直接 continue
    标脏该卷(v.dirty = true; v.dirtyTime = now);
  }
  CloseHandle(hDir);
```

- 缓冲区 64KB 起步；溢出频繁（A5）时 Phase 3 调 256KB–1MB。
- **溢出/错误一律标脏**，不丢"该卷有变化"的语义。
- **禁止** 在监听线程内直接重扫；只标脏。
- **退出打断**（C.1-2）：`CancelSynchronousIo(真实线程句柄)` → `CloseHandle(hDir)` → `WaitForSingleObject` join。**先 Cancel 后 Close**。

### 5.4 防抖、调度与可见期间实时生效

**调度线程**（全局唯一，串行化所有卷重扫，C6）：

```
调度线程循环（每 500ms 醒一次）：
  for each 卷 v:
    if v.dirty
       && (now - v.dirtyTime) >= DEBOUNCE_MS                    // 8000ms
       && (隐藏态 ? (now - v.lastRescanTime) >= HIDDEN_MIN_INTERVAL_MS   // 5*60*1000
                  : true):                                       // 可见态最小间隔=0（附录 C.3）
      v.dirty = false
      v.lastRescanTime = now
      RescanVolume(v)
```

**`RescanVolume(v)`**：
1. 调现有 `WalkVolume` 构建临时索引（内存）；
2. 写 `vol_X.idx.tmp` → `FlushFileBuffers`/`_commit` → `MoveFileExW(tmp, target, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`；
3. 替换失败（`ERROR_ACCESS_DENIED`/`ERROR_SHARING_VIOLATION`）→ 重试 3 次、间隔 200ms；仍失败记日志并保留 tmp；
4. **若窗口可见**（A4）：
   - 直接调用**已存在的** `CommitVol(v)`（附录 C.1-1，`:345`，`g_snap` 为 `atomic<shared_ptr<Snapshot>>`，本身即原子快照替换；**禁止新增 CommitVol、禁止自建读锁**）；
   - `PostMessage(hwndSearch, WM_APP+102, 0, 0)`；
   - 禁止释放临时索引（已移交快照）；
5. **若窗口隐藏**：释放临时索引，不碰内存快照。

**UI 线程收到 `WM_APP+102`**：重跑当前查询（复用 `SearcherThread` 启动路径）。**禁止** 在调度线程操作 UI 对象。

### 5.5 原子写盘与读盘改造

**改 `SaveVol`**：写完后 `fflush` + `_commit`（或 `FlushFileBuffers`）再 `fclose`；调用点用 `MoveFileExW(...REPLACE_EXISTING|WRITE_THROUGH)` 并加 3 次重试（200ms）。

**改 `LoadVol`**：改用 `CreateFileW`，`dwShareMode = FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE`（C5）；打开失败**降级为"无缓存"不崩**。

**`CommitVol`**：**已存在**（`:345`），直接复用，不得重写。若临时索引是 `Vol`，包成 `std::make_shared<Vol>(std::move(v))` 后传入。

### 5.6 退出路径（涉及主程序一处小改）

- 搜索进程显式退出（退出菜单或 `WM_APP+101`）：按 5.2 第 2 步收尾。
- 主程序 `App::Quit` 中，若搜索窗口存在，`FindWindowW(L"JisuqiFullDiskSearch", nullptr)` 取句柄后 `PostMessage(hwnd, WM_APP+101, 0, 0)`。**禁止** 发 `WM_CLOSE`（C9）。
- D1 已定"随主程序退出"，主程序退出后不应残留搜索进程。

## 6. Phase 2：设置来源统一（Phase 1 通过后）

**目标**：`settings.ini` 的 `[search]` 段作为搜索设置唯一权威；`config.ini` 只保留纯 UI 状态（窗口矩形、列宽、`sortcol/sortasc`）。

**步骤**：
1. 启动时读 `--datadir` 指向的 `settings.ini` 的 `[search]` 段，覆盖内存搜索参数；
2. 搜索参数变更写回 `settings.ini`，不再写 `config.ini`；
3. `config.ini` 只保留窗口/列宽/排序字段，删重复搜索参数；
4. 兼容：老用户 `config.ini` 残留搜索字段，首次启动迁移一次到 `settings.ini`（若后者无对应键），迁移后不再读。

**验收**：改 `settings.ini` 搜索参数 → 重启搜索插件 → 生效；`config.ini` 不再出现搜索参数字段。

### C.2 第 5 条微调（覆盖正文 C7 与 A1）

- **C7 改为**：关闭窗口时**必须** (a) 真析构 / `swap` 空容器释放大 `vector`（降 Private）；(b) 调 `EmptyWorkingSet(GetCurrentProcess())`（降工作集）。**两指标一起看**，不得只做 (b)。
- **A1 改为双指标**：关窗后 10 秒内——**工作集 < 50MB**（任务管理器"内存"列，即用户截图 122.7MB 口径）**且** Private 相对释放前**下降 ≥ 50%**；记录释放前后两组数值作为证据。

### C.3 第 6 条微调（覆盖正文 C10 与 A4）

- **C10 改为**：最小重扫间隔**仅对隐藏期**生效，`HIDDEN_MIN_INTERVAL_MS = 5*60*1000`；**可见期最小间隔 = 0**，只靠 `DEBOUNCE_MS = 8000` 防抖。
- **A4 保持"15 秒可见"语义**：可见期 8s 防抖后即重扫，不叠加 5 分钟间隔。代价是可见期高频变更时重扫频率上升、内存尖峰增多——按"运行时一百多 M 没事"接受。
- 注意：可见期重扫时旧快照若被搜索线程持有，新旧 `Vol` 短暂并存，瞬时可达 ~150MB，可接受，不处理。

### C.4 第 7 条微调（覆盖正文 D4 与 5.2 第 2 步）

- **D4 定为**：显式退出入口 = **标题栏关闭按钮（`idx 3`，`:1048`）上右键 → 弹出菜单"退出"**。现有三个标题按钮为自绘（最小化/最大化/关闭），关闭按钮仍单击=隐藏；右键才弹"退出"。
- 不新增托盘、不加菜单栏。
- 实现位置：在标题栏鼠标处理中判定 `idx==3` 的右键（`WM_RBUTTONUP` 或 `WM_CONTEXTMENU` 落在按钮区），弹 `TrackPopupMenu`，选中项 `PostMessage(WM_APP+101)` 走统一退出收尾。
- 同一退出收尾函数供"右键退出"和"收到 `WM_APP+101`"共用，避免两套逻辑漂移。
