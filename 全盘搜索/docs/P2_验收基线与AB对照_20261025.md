# 全盘搜索改造 · 验收基线与 P1a/P2 同条件 A/B（2026-10-25）

## 一、同条件 A/B（本次复核的核心）

方法：两个版本使用**各自独立的数据目录**（`--datadir=`），先在各自目录内完成一次全量建索引并退出，
再冷启动（从磁盘加载索引、无建索引干扰）测量；两轮交替顺序，排除环境漂移。

| 版本 | 轮次 | 开窗（已载入索引） | 搜 e 后（存 5 万条） | 关窗 10 秒 | 关窗窗口内 CPU |
|---|---|---|---|---|---|
| P1a（堆内索引） | 1 | **104.1 MB** | 122.0 MB | 93.7 MB | 62.0 s（正在整卷重扫） |
| P1a | 2 | **104.0 MB** | 122.0 MB | 36.4 MB | 2.7 s |
| P2（mmap + 分片） | 1 | **4.5 MB** | 16.1 MB | 5.3 MB | 13.9 s |
| P2 | 2 | **4.2 MB** | 15.6 MB | 5.7 MB | 8.8 s |

结论：
1. **P1a 开窗就是 104MB**（两轮完全一致，非偶然）：索引本体在堆里。
2. **P1a 关窗后是 36–94MB**，且两轮差异很大 —— 因为 P1a 是整卷重扫，关窗时若正在重扫就更高。
   P2 在 CPU 更忙（13.9s > 2.7s）的情况下关窗仍只有 5.3MB。
3. **所以 4.5MB 不是测量口径造成的假象**：同条件、同脚本、交替顺序下，P2 的开窗/关窗都稳定在 4–6MB，
   P1a 稳定在 104MB / ≥36MB。
4. 工作集：P1a 111MB（映射页在内），P2 39.6MB（索引是 file-backed 映射页，可被系统回收，不计专用内存）。

## 二、验收基线（定稿）

指标口径统一为 **专用内存**（任务管理器「内存」列 = Private Working Set）；
资源监视器的「工作集」在 P2 下会显示 ~40MB（mmap 映射页），属正常，不作为验收口径。

| 维度 | 指标 | 实测 |
|---|---|---|
| 静默（关窗 10 秒） | ≤ 13 MB | 4.5–6.2 MB |
| 开窗（索引已载入） | ≤ 20 MB | 4.2–4.6 MB |
| 搜索（5 万条封顶） | ≤ 60 MB | 15.6–16.9 MB |
| 热区新建文件→可搜到 | ≤ 30 s | 10–14 s |
| 热/温片重扫峰值 | ≤ 30 MB | 15.1 MB |
| **冷片（Windows Update 专用）重扫峰值** | **≤ 50 MB，仅 Windows Update 后或首次建索引时触发** | 47 MB |
| 搜索延迟 | ≤ P1a + 20% | 45 ms（P1a 41.4ms，+8.7%）|
| 分片 | C: 26 片 / D、E、F 各 1 片 | Σ片记录数 ≈ 全量（无重复）|

**明确不做**：冷片流式构建（把 47MB 压到几 MB）。理由：它只在 Windows Update 后触发一次，
收益是省一次不到 50MB 的瞬时占用，代价是把构建器改成"单遍写临时文件再拼接"，风险与代码量都不划算。

## 三、改造前后总览

| 项 | 改造前 | 现在 |
|---|---|---|
| 开窗（索引载入） | 104–120 MB | **4.2–4.6 MB** |
| 关窗后 | 36–94 MB（P1a）／早期版本关不掉进程 | **4.5–6.2 MB** |
| 搜索 5 万条 | 183 MB | **15.6–16.9 MB** |
| 新文件进索引 | 最多 5 分钟（早期：每 30 分钟整卷重扫） | **10–14 秒**（热区） |
| 单次重扫峰值 | 212 MB（整卷） | **15.1 MB**（热片）；冷片 47 MB |
| 打开索引 | 读 74MB 进堆 | mmap 26+3 个分片，约 1–2 ms |
